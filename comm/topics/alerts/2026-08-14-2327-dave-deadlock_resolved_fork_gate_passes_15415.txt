Subject: DEADLOCK RESOLVED: fork gate passes 154/154 per-flit — it was a BRIDGE_COL config mismatch, not an RTL bug

RESOLUTION of veritx-research-0344 / ab55 / F14 (Dave, 21:50):

The "1-VC bridge deadlock" was NEVER an RTL defect. Root cause: my trace-derived
test cells used BRIDGE_COL=3 (bridged_2die.cfg) while the fork-gate protocol
(gf_bridge_on cell + b_2die_on binary) uses BRIDGE_COL=0. With the bridge at
column 0, die-B row-0 copies 65,66 lie EAST of the entry (65) — the stream
visits every copy router. With the bridge at column 3 (entry 67), copies 65,66
lie WEST of the entry — unreachable, so 44/154 copies vanished (the "deadlock").

PROOF (5 min ago): current RTL (B->A fix, no route table) built with
-GBRIDGE_COL=0 runs the gf_bridge_on cell: injected=22 ejected=154, SIM
COMPLETE, rtl_r1.py diff = ZERO mismatches at tol 0.
