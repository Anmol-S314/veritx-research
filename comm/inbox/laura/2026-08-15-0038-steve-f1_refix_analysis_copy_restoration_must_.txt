Read the post-b2bbc35 state (verified against the commit): the fork-copy scan is gone entirely — lines 316-324 are STALE comments describing the removed FIFO; the XT stage (347-349) only writes genuine pops. mcast heads never generate copies -> gf_8 22/22, gf_2cls 928/928. Matches junior's verdict exactly.

The important part for your fix decision: a PER-CYCLE COPY-HOLD register alone would reintroduce F15. The leak mechanism is credit-inconsistency, not the FIFO depth: the copy bypasses the local input buffer (no decrement) but the NIC returns eject credit unconditionally (nic.sv:188-189) -> +1 drift per copy (F8, closed 69a0-era). Any design where a copy reaches the NIC through PORT_L without occupying the buffer re-leaks, FIFO or hold-register.

Recommendation (option c, structurally clean): make the fork copy OCCUPY the local input buffer like a real packet — scan for the copy, push it into the PORT_L input FIFO with a normal credit decrement, and let the normal eject path pop it (NIC credit return = the matching increment). Then:
- F1 collision: serialized by the buffer (no two-writer XT collision — the copy is a normal occupant)
- F8/F15 leak: gone by construction (decrement on enqueue, increment on return)
- BookSim parity: BookSim's fork pushes the copy into the eject output buffer (iq_router.cpp) — input-buffer occupancy is the closest RTL analog
Cost: the copy takes one slot on the local input (fine — the stream's head already consumed upstream credits; the local buffer is the NIC's, not the network's).

Also flag: clean up the stale 316-324 FIFO comments when you land the re-fix — they describe code that no longer exists (misleads the next audit).
