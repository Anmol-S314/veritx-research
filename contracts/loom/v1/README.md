# Loom JSON contracts (v1)

These JSON Schemas are machine-readable contracts. They describe authored project/run data, not claims that the corresponding UI or backend producer exists. Structured schema blocks reject unknown fields; application runtime validation currently covers only selected nested blocks. Add a versioned migration before changing file meaning.

## Project

- [`project.schema.json`](project.schema.json) is the project document schema. The project uses stable node/edge string IDs; edge `pipelineStages` is canonical on each edge. `schemaVersion` and `compilerSemanticsVersion` are independently versioned. A missing node `clock` serializes as explicit `null`; no workload, VC, access, or physical values are invented as defaults.
- `apps/studio/src/graph/copyPaste.ts` remaps copied stable IDs using the source ID and a deterministic collision suffix (`~copy`, `~copy-2`, …), rewrites internal edge endpoints and never derives identity from coordinates. Callers must use the returned IDs; this contract is tested at the graph/history layer, not wired to a browser clipboard flow.
- The project schema currently gives typed definitions for graph structure, project metadata (name, description and tags), catalog provenance/overrides/fallback metadata, agents/ports, clock/reset/power domains and crossings, VC/QoS, canonical access rules, the compatibility `firewall` field, floorplan geometry/hierarchy/keepouts/physical-edge metadata, and workload model/phase/communication/tensor/mapping/optional timing-hint fields. The runtime VC/QoS type is `VcConfigV1`; runtime validation covers selected nested semantics but not every optional field or cross-view producer.
- `parseProjectResult` is the non-throwing parser returning canonical project findings (syntax or semantic); `parseProject` remains a throwing compatibility wrapper. Neither function is a general JSON Schema engine.
- The canonical `access` block has unique integer precedence (lower value wins), explicit source/target node and optional agent scopes, `read_write` / `read_only` / `deny` effects, and a default policy. These are authored configuration values; no compiled access result is implied. The current web editor still writes its legacy `firewall` shape (`default: deny`, per-node `src`/`dst` and `RO`/`RW`) so the schema retains that compatibility field. Explicit migration maps only this supported deny-default node-pair shape, retains the legacy field and refuses to infer `access` from unsupported/ambiguous shapes.
- Floorplan rectangles use a project-declared `nm`, `um`, or `mm` unit. Node placements have stable node IDs, bounds, lock state and optional hierarchy; hierarchy membership, keepouts, die outline and authored edge route metadata round-trip. These values are not claims of measured physical layout or signoff.
- [`validation-issue.schema.json`](validation-issue.schema.json) defines the common severity/code/message/object-reference shape and permits quick-fix metadata only when explicitly marked safe. The M0 project, workload, trace-event, run-manifest and summary validators return this structured model; project findings retain a legacy `path` alias for existing consumers. Project runtime validation checks selected nested workload phase/timing/tensor/mapping constraints (including communication-op references), VC/QoS identifiers/arbitration references, domain definitions/crossings and floorplan geometry/hierarchy. Broader nested-schema enforcement and compiler consumption remain incomplete.

## Run artifacts

- [`trace-event.schema.json`](trace-event.schema.json): one v1 event per JSONL line; cycle, metric family, traffic class, numeric value, and a stable `node_id` or `edge_id` are required. Phase/run IDs are optional. `parseTraceJsonlResult` returns canonical findings with exact line-qualified paths; `parseTraceJsonl` remains its throwing compatibility wrapper. Mock frame objects are a separate format and are not production trace events.
- [`summary.schema.json`](summary.schema.json): run/backend provenance, aggregate metrics, warnings, and explicit estimated/unsupported flags. An unsupported metric has `value: null`; the schema does not authorize synthesizing a value. `apps/studio/src/graph/summary.ts` validates summaries into canonical structured findings and enforces those constraints; a runtime run-summary producer is not claimed.
- [`run-manifest.schema.json`](run-manifest.schema.json): intended reproducibility record with project fingerprint and versions, engine/UI/backend provenance, argv command, seed, inputs and artifact hashes. `apps/studio/src/graph/runManifest.ts` provides a typed builder, canonical validator and deterministic serializer; it derives project versions/fingerprint and hashes supplied artifact bytes, while callers supply all run facts. No backend run producer is wired to it yet.
- [`provenance.schema.json`](provenance.schema.json): canonical measured/simulated/estimated/mocked/unsupported/blocked states and UI truth rules. Consumers still need to adopt it consistently.

## Golden fixtures

`apps/studio/src/graph/fixtures/` stores the small custom graph, 8×8 mesh, multi-domain graph, floorplanned graph and workload-bound graph fixtures. `loom-golden-projects.contract.test.ts` validates each document and verifies edit → serialize → reload semantic equality while preserving stable node/edge IDs.

## Migration and serialization

The explicit migration API is `apps/studio/src/graph/migration.ts`. It previews deterministic before/after documents, ordered migration steps, and a stable path-based added/removed/changed diff for supported legacy v0 and early-v1 shapes; it folds `pipelineStagesByEdge` only when unambiguous and converts only the known node-pair deny/RO/RW firewall shape to canonical access while retaining legacy data. Unknown forms are preserved unchanged. `apps/studio/src/graph/migration-fixtures/v0-side-map.json` and `v0-side-map.v1.json` are the preserved expected v0 input/current-version output fixture pair. The API returns data; callers must save to a new destination. This API diff is not a Studio preview/diff/save-as interaction and no browser E2E is claimed.

Project serialization applies the current graph/runtime validator, sorts object keys deterministically, preserves semantic array ordering, and normalizes only absent node clocks to null. `fingerprintProject` computes lowercase SHA-256 over that canonical serialization for content identity. It is not a general JSON Schema runtime validator. The full project Schema was separately meta-validated and the golden fixture files were validated with Draft 2020-12 tooling. It deliberately does not pretend omitted workload/domain/access/floorplan data has a known default.
