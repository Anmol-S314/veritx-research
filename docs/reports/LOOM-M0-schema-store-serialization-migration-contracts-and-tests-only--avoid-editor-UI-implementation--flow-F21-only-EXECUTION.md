## Work implemented

- Added required `compilerSemanticsVersion: 1` to the project type/validator and current schema document; presets and graph-to-project conversion now produce it. Unsupported project/semantics versions have migration-directed validation messages.
- Added deterministic object-key serialization while preserving authored array order (especially node/edge ID order). Normalizes the unambiguous missing-node-clock default to `null` and exposes `fingerprintProject`, lowercase SHA-256 of canonical serialization; intentionally does not infer unspecified workload, VC, access, or physical semantics. Tests prove canonical key/default equivalence and content-change sensitivity.
- Added `cloneGraphFragment` for deterministic collision-free node/edge IDs (`source~copy`, then collision suffixes), endpoint remapping and unknown-endpoint refusal. Tests prove coordinates do not influence IDs and the graph-history paste/save-load path preserves the resulting IDs. No browser clipboard/UI integration was added.
- Added non-mutating migration preview and explicit migration API for supported legacy v0 / early v1 projects. It adds missing compiler semantics version, handles missing `presetHint`, folds the historical `pipelineStagesByEdge` map, and converts only the exact known legacy deny-default node-pair RO/RW firewall shape to canonical `access` while retaining the original firewall field. Unknown firewall forms stay unchanged. Conflicts, dangling side-map references, malformed input, invalid projects, and future versions refuse without touching source; preview returns before/after text, ordered steps, and a deterministic path-based diff against canonical output. Stored v0 fixture proves source preservation, diff coverage and supported transformations; broader historical formats are not claimed.
- Added focused migration/deterministic-serialization tests, including proof that serialization has one canonical `pipelineStages` property per edge and refuses a non-canonical side map.
- Defined trace JSONL v1 in `contracts/loom/v1/trace-event.schema.json`; added typed per-line validation/parsing with exact corrupt-line diagnostics, stable node/edge IDs, cycle, metric family, traffic class and optional phase/run IDs. Added a typed summary model and canonical validator that enforces these truth constraints; no run-summary producer is claimed.

- Added a shared canonical `ValidationIssue` model and v1 JSON Schema with severity/code/message/object reference and safe-only optional quick-fix metadata. Project, workload, trace-event, run-manifest and summary validators return that shape; graph-history outcomes, graph-to-compiler adapter refusals, and the non-throwing migration-preview API carry structured issues alongside legacy `refused` text/throwing compatibility. Project and trace-JSONL parse-result APIs return structured syntax/validation findings with exact source paths/lines. Project findings retain the legacy `path` alias.
- Hardened project JSON-value validation against cyclic references, over-depth metadata and non-plain object prototypes so direct API callers get structured refusal rather than recursion overflow or accidental serialization coercion.
- Defined the six-state evidence provenance enum and explicit UI truth rules (mocked, estimated, unsupported, blocked, etc.) in a versioned contract; this is not wired into every view/result.
- Added typed `VcConfigV1`/virtual-channel/traffic-class/arbitration models and the matching project schema for VC IDs/depth/class/escape status, traffic-class→VC/QoS mapping and per-class priority/weight inputs. Runtime validation checks required/nested values, stable-ID uniqueness, VC/traffic-class references and arbitration-table keys; tests cover canonical findings. - Added `contracts/loom/v1/README.md` documenting supported schemas, migration bounds, serializer defaults, and explicit schema coverage gaps. Added a project-schema surface regression test asserting version fields and every M0-01 top-level data section/definition are present.
- Added typed clock/reset/power domain and crossing-policy interfaces plus schema blocks, node and stable port domain assignments, and edge crossing policies. Runtime validation checks nested field types/unknown keys, duplicate and dangling domain/port references, duplicate assignments, resolves port assignments against declared agent ports when available, validates crossing-policy shapes/elements, and checks floorplan hierarchy membership; full editor port-model integration remains incomplete.
