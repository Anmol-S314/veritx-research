## Important reconciliation notes

- This workbook describes a production **desktop/Tauri** Loom with local project files, a `loom-sim` sidecar, trace playback, physical flow, signed updates and installers. Current `apps/studio` is a **web** React/Vite Studio tied to the VeritX gateway, plus a local graph authoring slice; those are related but not interchangeable products.
- `GraphLoom.tsx` explicitly labels its graph as local authoring and says it cannot be applied/compiled without lossless migration. Thus local graph editing cannot be used as proof of canonical project save/reopen, workload integration, or engine execution.
- `docs/product/LOOM-CAPABILITY-CLOSURE.md` identifies materialization/execution and product persistence/UI as open for multiple V5 fields; its own evidence separates structural intent from qualified execution.
- Browser smoke/route checks and backend simulation tests are not substitutes for the specific 24 workbook user journeys. Each journey needs a runnable E2E script on the production surface, asserting its stated pass condition.
- Do not update tracker task Status to Done from this audit. Recommended next step: revise tracker scope to separate (1) existing VeritX web Studio, (2) proposed standalone desktop product, and (3) scientific/backend qualification; then have an owner attach acceptance evidence per item.
