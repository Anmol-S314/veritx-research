## Scope and baseline findings

Scope ledger covers 89 tasks: all M6 and M7 tasks; M8 workspace/file/recovery/export/bundle tasks; plus engine-specific M8-21 and offline-core M8-22/23. M8 general settings task M8-20, navigation M8-24, and all other milestones/runners are excluded. F11–F17 and F22 (8 flows) are in scope. Tracker priority, dependency, title, and acceptance wording are copied below. Initial task status is the tracker status.

The checkout is a web Studio (React/Vite); `package.json` describes fixture-backed UI with no engine connectivity. `src/graph/trace.ts` only generates deterministic MOCK traces, not a real backend trace parser/runner. `src/graph/io.ts` uses browser downloads. No Tauri app/typed command surface is present in the inspected Studio tree. Consequently desktop shell, sidecar, native picker/atomic-save, signed packaging and physical-tool requirements cannot be closed by web-only substitutes. Existing project parser/validator is not equivalent to recovery or engine provenance.

## Blockers and truth constraints

- A real BookSim/ASTRA run, engine handshake/sidecar lifecycle, and real trace provenance require executable integration not present in this web-only application; mock data must remain explicitly MOCK and is not physical evidence.
- Tauri-specific commands, native file dialogs, crash recovery on application restart, and shell-owned exports require a desktop shell. Browser downloads do not satisfy those criteria.
