## 0.1 Verdict after the grant-pipeline RTL change (2026-11-10, third pass, run 5)

**The router's combinational grant/esc_starve chains were pipelined in `tracks/t3-topology/rtl/mot_htree/router_template.sv`; post-CTS setup slack improved −6.02 → −4.42 ns and TNS −24,703 → −11,389 ns; hold stayed clean. Changes (router template only, function-preserving):

1. **Grant pipeline.** The per-output-port esc/free grant decision is now a register stage (`stage A` comb scan producing `esc_valid/esc_pick/esc_vc` / `free_valid/free_pick` / merged `grant_valid/grant_sp/grant_sv` / `grant_valid2/grant_sp2/grant_sv2`, feeding a new `stage B` always_ff that re-registers all of them into `*_r` signals). All grant consumers (output-stage loads, the `grant_deq_q` dequeue mark feeding ejection-skip and the enqueue race, the `esc_stage_vc` latch, the trace-stuck diagnostics) read the registered decision only. The queue front cannot move between decision and use (only this grant dequeues it), so a one-cycle-old decision cannot name a stale queue. Grants now cost +1 cycle per hop vs. before.
2. **Explicit registered wire-priority state for the starve guard.** The `esc_starve` counter + `show_vc` comb feedback was replaced by a registered `esc_yield_q` state bit per output port: the escape class holds the wire; after ESC_YIELD_K (4) consecutive cycles with both classes occupied, `esc_yield_q` arms a one-cycle free-class window, then clears. `show_vc` is now a shallow comb off `out_valid_all` + `esc_yield_q` only (no comb dependence on the counter), and the dwell counter updates from registered state only — no combinational loop, inferred latch-free. The 4-VC widening path (`apply_router_widening` in `product/project_top_rtl.py`) was extended to generalize the dwell condition to `out_valid_all[po][1] || [2] || [3]` for the VC≥2 case (the old string-replaces no longer matched the rewritten guard).
3. **`run_rtl_slice` fix.** None required (the pipeline needed no post-processing hook); the composed-slice sim source (`router.sv`) is a verbatim copy of the template.

- **`CLOCK_PORT = clk`, not `noc_clk`**: the task brief's `noc_clk` is the manifest's clock *name* ("single clock noc_clk"); the Verilog port is `clk` (`project_top.sv:446`). LibreLane requires the real port name — `noc_clk` would fail immediately.
- **`CLOCK_PERIOD = 10.0` ns**: *assumed, not measured from the repo.* The manifest explicitly says `default_clock_freq_mhz` stays an assumption (STA "not established"). Nothing in the repo defines a period; the brief's example (10 ns) was used uniformly.
- **No SRAM macros**: the only memory is a behavioral `logic [31:0] sram [0:255]` in `destination_adapter.sv`. LibreLane synthesizes it to flip-flops (no macro needed); memory did **not** block synthesis (see §5). It is implicated in the later congestion failure.
