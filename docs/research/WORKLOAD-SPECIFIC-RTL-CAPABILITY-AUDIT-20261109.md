# Workload-specific RTL and Design controls: capability audit

## Verdict

**There is real implementation here, but not yet a connected workload-specific RTL product.** The main missing work is not filling the Design page or adding fields. It is carrying an exact resolved project contract into a composed hardware top, enforcing that contract on real transactions, and verifying the result.

Eight independent technical reviews were used; final design judgment and reconciliation are the parent's. Concurrent edits landed during the first six reviews, so two more reviews examined a new coherent snapshot rather than repeating obsolete “module absent” conclusions. Latest cohort: **2026-11-09 07:09:03 UTC**, 1,082 files; its pinned paths still matched the working tree at the final drift check. Another snapshot pins 128 previously compiled Scala/build files. These snapshots are audit inputs, not qualification certificates.

Here **M1–M4** mean the Design-page address/access, traffic/ordering, domains, and protocol concepts—not the separate original12 RTL program's milestone numbering. Passing the twelve research profiles would not automatically establish arbitrary per-project protocol/security/domain configuration.

## Highest-priority findings

### 1. New M1–M4 files are not the composed design

`tracks/t3-topology/dse/veritx_dse/product/rtl_export.py` plans and writes decoder/CDC/adapter/ordering source files and lints those modules separately. The actual network top is generated by `scripts/rtlgen/gen_rtl.py` → `rtl/mot_htree/gen_rtl_htree.py`; its construction connects routers/local flit ports, not those endpoint-policy modules.

The network lint invocation names only `noc_pkg.sv`, `router.sv`, and `noc_top.sv`. The M2 generator patch adds `ORDERING_*` constants/comments and JSON metadata; it explicitly leaves route tables unchanged and relies on the separately emitted FSM to select VC. **There is no demonstrated consumer making those policy constants govern the delivered network traffic.**

Therefore “module emitted,” “listed in archive,” “hash changed,” or “lint passed” cannot be displayed as “policy realized in this design.” Either connect the modules into the delivered project top and verify it, or accurately label them standalone previews.

Evidence: latest `product/rtl_export.py:90–129,173–210,255–322,390–430`; `scripts/rtlgen/gen_rtl.py:324–380`; `rtl/mot_htree/gen_rtl_htree.py:208–245`.

### 2. Fine-grained region access is not implemented correctly yet

The request can associate permission windows with an agent group, but compiler/emitter paths flatten the windows. The renderer keys policy by **range name**, not `(trusted requester, range)`; its inputs are address and read/write direction, not requester identity. Two different policies for one region are rejected as duplicate windows.

I executed the actual frozen renderer: read-only versus write-only changes generated logic, but there is no initiator input, and two policies for `shared_region` raise `duplicate permission window`. That is useful range-level logic, **not per-initiator access control**. The decoder is also not shown connected to real traffic.

Required semantics:
- Trusted initiator identity at the NI/ingress, including group versus instance granularity.
- Region ownership and per-initiator read/write—and atomic/other operations only when the chosen protocol supports them.
- Explicit default policy, unmapped/denied behavior, and full-burst containment/split rules.
- Denied requests never reach a target; error completion cannot strand an outstanding transaction.

Implementation may use a source-keyed policy or correctly configured per-ingress instances; a new runtime ID input is not the only valid design. What matters is preserving trustworthy identity all the way to enforcement.

Evidence: `product/rtl_export.py:164–165`; `product/addr_decode_rtl.py:66–91,150–167,208–276`; `model/agent_intent_v4.py:120–165,182–290`. Probe: `reports/parent-permission-probe.json`.

### 3. OrderingFSM has a concrete ready/valid defect before integration

Generated equations include:

```systemverilog
in_ready = out_ready && !outstanding_full && ordering_permits;
out_valid = in_valid;
```

With `in_valid=1`, `out_ready=1`, and either a strong-order violation or full outstanding capacity, **upstream acceptance is false while downstream acceptance is true**. A source holding its beat because `in_ready=0` can therefore have that beat consumed repeatedly downstream. This contradicts the claimed stall/backpressure enforcement.

This is a source-linked combinational counterexample, not an HDL simulation. Forwarding permission must govern both sides of the transfer consistently. Add actual RTL tests for this case before connecting the block. Also define the sequence field, ordering domain, outstanding transaction unit, completion association and wraparound; a generic pulse/global counter does not establish arbitrary protocol ordering. Splitting flit-type bits is not by itself safe transaction splitting.

Evidence: `product/ordering_fsm_rtl.py:311–394`. Probe: `latest/reports/parent-ordering-handshake-counterexample.json`.

### 4. Protocol selection needs real endpoint semantics

The new AXI-style shim is a bounded primitive, not a full protocol adapter: it exposes AW/W and bare B valid/ready, without a complete read/response/ID/framing contract. Missing WLAST/beat association and response reconstruction matter when splitting one original transaction into multiple sub-bursts. Width parameters changing an isolated module do not prove correct packetization into the 64-bit network.

Choose and document an exact initially supported protocol subset, reuse compatible existing library primitives, and connect it to the NI. Verify IDs, outstanding bounds, requests/responses, byte enables/last, burst boundaries, errors, backpressure and width conversion. Keep CHI/TileLink/custom unsupported on a path where no adapter is actually connected; do not infer global absence of library support from an SV-only search.

Evidence: `product/adapter_factory_rtl.py:132–201,242–286`; Scala `protocol/AXI4.scala`, `protocol/TilelinkAdapters.scala`, `channel/WidthWidget.scala`.

### 5. CDC insertion must be a real crossing, not an inventory entry

A FIFO wrapper in the ZIP is not an endpoint crossing. The actual domain clocks/resets and data/control handshake must pass through it. Verify unrelated clock ratios/phases, full/empty behavior, reset skew, held traffic and conservation. The new code itself discloses that nominal depth8 has usable capacity4; workload admission and UI must use actual usable capacity.

A declared frequency can legitimately affect constraints/test clocks without changing Verilog, but that does not establish achieved frequency, MTBF or timing closure. Power isolation/retention/level-shifting remain separate technology-backed obligations; do not populate invented physical metrics.

Evidence: `product/cdc_cell_rtl.py:166–186,254–266`; `rtl/cdc/cdc_fifo.sv`; `product/rtl_export.py` assumptions and separate-cell lint paths.

### 6. Workload-specific must mean a resolved, checked hardware fit

Existing workload/optimization paths are useful. They can choose topology or buffer settings and evaluate modeled outcomes. But the product path still lacks the complete binding from workload requirements to endpoint, protocol, ordering, width, domain and routing/VC realization.

Separate:
1. **Hard semantics:** identities, access policy, protocol/version/features, request/response ordering, clocks/resets, allowed traffic.
2. **Workload envelope:** sizes, bursts, overlap/concurrency, outstanding demand, rates, dependencies, service/latency targets, mapping.
3. **Legal tuning degrees:** topology, placement, widths, buffers, VC/vnet budgets, pipeline/arbitration, supported clock constraints.
4. **Derived implementation:** actual route/VC assignment, packetization, adapters, decode tables and crossings.

Do not infer permissions from a trace that happened not to perform a write. Do not expose arbitrary VC/routing choices without coupled legality/deadlock checks. Distinguish model predictions from observed RTL and physical results.

Not every workload change should force different RTL: the resolver may legitimately select the same sufficient design. Prove that requirements are consumed and satisfied; choose directed mutations with known hardware/configuration effects for validation.

Evidence: `workload/intent_lowering.py:198–217,298–357`; `optimization/real_evaluator.py:205–250`; `product/rtl_export.py` generator invocation.

## Recommended implementation order

1. **One immutable resolved project model and one real elaboration owner.** Every relevant semantic requirement and selected hardware value has a consumer or a typed blocker. `PerProjectElaborator` is a sensible owner name, but it must build the actual composed top, not wrap the fixed preview with extra sidecar files. Internally own tool invocation, family construction, partition/reassembly, source/resource closure and complete manifests. Do not make callers duplicate derived values or pass inconsistent request/bundle pairs.
2. **Finish one end-to-end vertical slice.** One supported mesh/profile, one explicitly specified protocol subset and one clock; two initiators + one memory target, the same region with different permissions, real request/response handling, real NI/NoC wiring and workload traffic. Prove allow/deny, errors, ordering, backpressure and conservation on that composed top. This is a development milestone, not “fully fledged” completion.
3. **Parameterize supported architecture and close proofs.** Bind actual attachments, family routing law, data/flit/header widths, buffer capacity, VC/vnet allocation and scheduling. Re-run physical-resource/progress and protocol-dependency checks when these change. Then add real multi-domain/width and shared-resource realizations incrementally.
4. **Expose controls from a backend-owned capability report.** Enable a control only at its actual supported phase/scope. Avoid separate UI tables claiming support and backend registries refusing it. Fix stale blocker text without prematurely enabling incomplete hardware.
5. **Deliver exact evidence/reproduction.** Project/revision/workload/constraints/source/tool identities, composed top/helpers, configuration image/constraints where applicable, behavioral results and actual fresh reproduction. Lint, hash differences and five-packet conservation are limited checks, not whole-design equivalence.

## What the Design workspace should become

A configurable engineering workspace, not a wall of populated facts:

- **Addresses & access:** editable regions and trustworthy initiator × region permissions, instance/stripe targets, conflicts and explicit error/default policy.
- **Traffic & ordering:** real workload traffic graph/envelope, ordering domains and request/response constraints; legal capacity tuning. Derived VC assignments read-only by default; advanced requests must be validated/proved.
- **Interfaces:** actual endpoint role, supported protocol subset, widths, burst/outstanding/ID requirements and inserted adapters.
- **Clocks & resets:** domain assignment, required crossing behavior, actual inserted cells, usable depth and constraint/test assumptions. Physical power features stay visibly unsupported until implemented.
- **Resolved hardware/evidence inspector:** for each requested value show actual resolved value, provenance (workload/manual/default/derived), consuming RTL instance/configuration/constraint, and evidence level: declared → validated → emitted → connected → behaviorally tested. Save success is not hardware readiness.

Keep useful topology/mapping visualization; collapse unrelated unevaluated physical metrics. Support manual locks/overrides explicitly, with recompilation and invalidation. Preserve exact 64-bit addresses across the UI/wire format; current `parseAddress` converts accepted BigInt values into Number before safe-integer validation (`apps/studio/prototype/src/agentMap.ts:84–98,239–247`). Canonical exact strings/typed parsing are preferable to rounding valid addresses.

## Acceptance checklist for the developer

- [ ] Every offered knob has a roundtrip, exact validation, a resolved value, a real consumer and an explicit unsupported path.
- [ ] Composed-top hierarchy shows intended NI/decoder/permission/order/adapter/CDC instances on real traffic paths.
- [ ] Two initiators with opposite rights to one region produce distinct allowed/denied behavior, including bursts/unmapped/error completion.
- [ ] Ordering/outstanding tests check both upstream and downstream accepted events; no duplicate acceptance under blocked input.
- [ ] Protocol tests cover the exact supported transaction subset, response/ID/last/error behavior and width adaptation.
- [ ] CDC tests use actual asynchronous clocks/reset/backpressure and exact usable capacity; no implied STA/MTBF.
- [ ] Workload requirements and manual overrides are accounted for in resolved hardware; model/RTL measurements stay separate.
- [ ] Legal VC/routing/resource/protocol constraints are reverified after structural changes.
- [ ] Directed parameter mutations alter connected behavior or real programmed configuration/constraints—not just comments or hashes.
- [ ] New project revisions invalidate prior hardware evidence; no current-project readiness inferred from research catalog files.
- [ ] A fresh invocation reproduces the complete delivered design and its declared evidence.
