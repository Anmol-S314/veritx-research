# F2 Mini-Cell Design — Deterministic Reorder+Mcast Corner Test

Status: DESIGN (write-only; implementation follows)
Owner: opencode (senior)
Date: 2026-08-13

## 1. Purpose

Deterministically exercise the F2 corner in `rtl/nic.sv`: the `consumed1`
reorder path when the reorder-fired entry (tptr+1) is a **mcast stream**
whose range word sits at tptr+2. The F2 bug (fixed edec5c1/4f951e1): the
consumed1 advance skipped +2 blindly and parked tptr on the range word
forever (replay deadlock). The statistical two-class cell cannot guarantee
this corner; this cell forces it by construction.

## 2. Why the corner needs a UNICAST entry at tptr

The reorder condition (nic.sv ~line 420) requires:
- `trace_mem[tptr+1]` to be a REAL entry (`cycle != 0`) — a range word at
  tptr+1 blocks the reorder;
- both classes pending-free, both due at current tick, different classes;
- rotation-next class == class of tptr+1.

In an ALL-MCAST trace every entry's range word occupies tptr+1, so the
reorder can never fire. The corner therefore requires:

```
tptr   = unicast cl1 entry (real, no range word following)
tptr+1 = mcast cl0 entry (its range word at tptr+2)
```

with the cl1 entry's VC pick BLOCKED at tick T (so it defers via
consumed1) and the cl0 mcast firing first (rotation serves cl0 when
last_class was 1).

## 3. The cell (NIC 0 only, 8x8 mesh, VCS=1)

### 3.1 Trace entries (trace_n0.hex, 64-bit words)

| idx | word (hex) | meaning |
|-----|-----------|---------|
| 0   | `0000002800010001` | cl1 unicast (dst 1, size 1) at cycle 40 |
| 1   | `0000002800020003` | cl0 mcast stream (far end 3, size 1) at cycle 40 — same tick |
| 2   | `0000000001020000` | range word: copy_lo=1, copy_hi=2 (cycle=0 marks it) |

Note: the mcast entry at tptr+1 has its range word at tptr+2 — the exact
layout the F2 bug mishandled.

### 3.2 Forcing the deferral (VC block at tick T=40)

The cl1 entry at tptr must NOT be able to fire at tick 40. Mechanism:
a multi-flit cl1 burst (size 3) fired EARLIER (cycle 20) whose head is
mid-flight at tick 40, owning the router's local VC (in_use). The cl1
unicast at tptr then shares the VC and its pick fails (`vc_owned`).
Add the burst BEFORE the pair:

| idx | word | meaning |
|-----|------|---------|
| -   | `0000001400010003` | cl1 burst (dst 1, size 3) at cycle 20 — occupies the VC |

Full order: burst (cycle 20), cl1 unicast (cycle 40, tptr), cl0 mcast
(cycle 40, tptr+1), range word.

### 3.3 Forcing the rotation order (last_class = 1 before T)

The reorder fires when `((last_class+1) % CLS) == class of tptr+1` (cl0).
So last_class must be 1 at tick 40. The cl1 burst at cycle 20 injects its
flits over cycles 21-23, leaving last_class = 1. No other class-0 traffic
before T.

### 3.4 Expected behavior (with the F2 fix)

- Tick 40: cl0 mcast (tptr+1) fires first (rotation), cl1 unicast (tptr)
  defers (VC blocked by the burst) → consumed1 = 1, tptr stays at idx 0.
- Tick 41 (burst tail done, VC freed): cl1 unicast fires (f0=1).
- consumed1 advance: `tptr <= tptr + 2 + (range at tptr+2 ? 1 : 0)` = +3.
- tptr lands on the '1 padding (empty) → replay stops cleanly.

### 3.5 Expected behavior (F2 bug present — for negative control)

- tptr advances +2 → lands on the range word at idx 2 (cycle==0).
- The range word never fires AND never advances → replay deadlocks at the
  range word; entries never complete; R1 SIM COMPLETE never prints.

## 4. PASS/FAIL assertions

1. **FIRE lines**: `FIRE n0 tptr=0 cl=1 cycle=40` then `FIRE n0 tptr=1
   cl=0 cycle=40` — both entries fire.
2. **R1 SIM COMPLETE** printed (no deadlock).
3. **Drain totals**: injected = 1 (mcast stream) + 1 (cl1 unicast) + 3
   (burst) = 5; ejected = 5 + 2 copies = 7 (stream at far end 3 + copies
   at 1,2 + cl1 unicast + 3 burst flits).
4. **No "FAIL R1 ejected != injected + fork delta"**.
5. Negative control (build pre-F2-fix): run hangs, no SIM COMPLETE.

## 5. run_cycles

`300` is ample (T=40, all deliveries < 100 cycles on 8x8).

## 6. Wiring into rtl_r1.py

The cell is a handcrafted trace — do NOT use gen-trace (it would
overwrite trace_n0.hex). Flow:
1. Write trace_n0.hex by hand (table above).
2. Run `rtl_r1.py gen-trace` is SKIPPED; instead: the RTL binary
   `+run_cycles=300` directly in the cell dir.
3. BookSim truth: flits.txt must be generated by hand or by a BookSim run
   with the same traffic — simplest: hand-write flits.txt with the 7
   expected deliveries (pids: burst 0-2, cl1 unicast 3, stream 4, copies
   5-6) since the cell is a known-answer gate.
4. `rtl_r1.py diff <cell>` — expect ZERO mismatches.

Simplest honest route: a standalone run + assertion on the log lines
(FIRE count, SIM COMPLETE, totals), since the diff needs the matching
BookSim truth which is trivial to hand-derive for 5 packets.

## 7. Known limitations

- VCS=1 only (the corner is VC-orthogonal; VCS=1 keeps the NIC debug
  `free[1]` OOB issue away — that's fixed by R1_DEBUG anyway).
- The cell validates the pointer advance, not delivery timing — timing
  correctness is the single-stream gate cells' job.
