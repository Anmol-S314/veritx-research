Default Build Matrix function:
The current implementation of build_traffic_matrix() is a placeholder designed only to enable
the Timeloop to BookSim pipeline to be able to run. It does not derive communication from the
computation or mapping generated by Timeloop. Assumes a fixed communication pattern
where 60% of traffic is exchanged between neighbouring tiles and 40% is directed to a single
memory-controller (assumed node 0).

The model uses only the aggregate DRAM access count reported by Timeloop. It completely
ignores which tensor is being accessed by which tile and how the computation is spatially
distributed across tiles. This doesnt match how our neural network works or how our workload
runs or what operations are present in our workload.

The final build matrix function should be able to do the following:
  -​ Get the total number of dram accesses per operation
  -​ Have an understanding of which tiles are accessing this data ( we will do this by making
      sure the problem.yaml is per tile specific), in case there is data sharing between tiles it
      should be aware of that.
  -​ Finally map accesses for each tile in two categories, Off chip ( Dram to tile ) and inter
      tile ( for data sharing when needed between tiles )



Attention Mapping Spec:
Mapping: 16 tiles, 32 heads - 2 full heads per tile (chosen for least inter tile
communication)

keeping full heads per tile confines all attention math to local computation and pushes the
only unavoidable communication to one place (the output projection)

So we compute attention locally for all heads in their specific tiles till we get the head outputs.
The next step is to concatenate the outputs of each head to get the original tensor size and
then do a matmul with Wo ( output weights ). Instead of doing this we wont move the head
tensors anywhere, instead we will shard the output matrix into rows that will match the size of
each head then send these to the tiles. The output of this operation will be of the correct
output that we were initially getting but will be a fraction of it, so we need to add up all the
output matrices after doing this step to get the correct output which wouldve resulted from the
standard procedure of concating and then matmul with Wo. This is the first step where we will
need data from multiple tiles.
