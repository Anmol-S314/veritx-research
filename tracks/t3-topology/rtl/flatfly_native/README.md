`flatfly` here is the canonical materialized 4-ary, 2-dimensional flattened butterfly: `radix_per_dimension=4`, `dimension_count=2`, `concentration=1`, hence 16 routers and 16 attached endpoints. The router numbering is `x + 4*y`; each router has direct bidirectional links to the other three routers in its row and column. This is a graph-native fabric, not the separate staged BookSim `fly` network.

The RTL models a one-flit packet: an accepted flit is a complete packet with a destination endpoint tag. Routers use dimension-order routing, first changing the least-significant (`x`) digit, then `y`, then ejecting at the destination router's single local endpoint. Each of seven physical inputs has one elastic slot and outputs arbitrate round-robin. No multi-flit framing, VCs, adaptive routing, or performance/PPA claims are made.

Run `./verify.sh`. It first checks all 96 directed channel/port pairings and 256 dimension-order routes, then compiles in a uniquely-created `mktemp` directory under `${JCODE_SCRATCH_DIR:-${TMPDIR:-/tmp}}` and removes it on exit. The RTL test sends all 256 ordered endpoint pairs under deterministic egress stalls, checking payloads, accepted/delivered conservation, no duplicates/loss, and drain.
