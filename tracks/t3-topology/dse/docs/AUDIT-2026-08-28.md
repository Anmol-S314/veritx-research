# DSE Harness Audit — 2026-08-28

## CRITICAL: What's Fake

### 1. Packet Size is Wrong (BIGGEST ISSUE)
The converter caps ALL packets to 8 flits (512 bytes), but the raw sizes are:
- ALLREDUCE: 8MB = 131,072 flits = 16,384 packets
- ALLGATHER: 2.2MB = 35,840 flits = 4,480 packets
- REDUCESCATTER: 8MB = 131,072 flits = 16,384 packets

**We're sending 1 packet of 8 flits instead of 16,384 packets.** This means:
- BookSim sees 98K packets instead of ~10M packets
- Congestion is massively underestimated
- Latency numbers are unrealistically low

**Fix:** Remove the MAX_FLITS_PER_PKT cap. Let packets be as large as the raw size (capped at 512 flits = 32KB for manageability).

### 2. LLaMA C*_R* Traces are Synthetic
All `llama_C*_R*.trace` files have identical pattern (node 0 → node 1,2,3,...,9) with only packet size varying. These are NOT real LLaMA traffic — they're generated with a fixed pattern.

**Real traces:** `llama_1b_15all_960.trace` (960 pkts, 64 src/dst) is real.

### 3. cli_test.trace and input.trace are Identical
Both have 184,345 pkts with same distribution. Duplicates.

### 4. Speedup Factor Compresses Time
Expert compute: 553,758 us = 553ms real time → 5,537 cycles with speedup=100.
This compresses the timeline but preserves relative ordering. Acceptable for DSE but not for timing analysis.

## Missing Knobs

### 1. Packet Size (not a knob yet — hardcoded to 8 flits)
Should be: 4, 8, 16, 32 flits (512B – 4KB)
Impact: Larger packets reduce header overhead but increase per-hop latency.

### 2. VC Count (hardcoded to 4)
Should be: 2, 4, 8 VCs per port
Impact: More VCs = more parallelism but more buffer area.

### 3. Injection Rate (not modeled)
Real NoCs have injection queues with backpressure. Our traces inject at fixed cycles without backpressure.

### 4. Wire Latency (hardcoded to 1 cycle)
Real NoCs have wire latency that scales with distance. GEC express links should have lower latency than mesh links.

### 5. Buffer Size (hardcoded to 8 flits per VC)
Should be: 4, 8, 16 flits per VC
Impact: Larger buffers reduce blocking but increase area.

## Improvements Needed

### 1. Fix Packet Sizes (P0)
Remove MAX_FLITS_PER_PKT cap. Let packets be:
- ALLREDUCE: 8MB / 64B = 131,072 flits → cap at 512 flits → 256 packets per op
- ALLGATHER: 2.2MB / 64B = 35,840 flits → cap at 512 flits → 70 packets per op
- This gives ~10M total packets instead of 98K

### 2. Add Wire Latency Model (P1)
GEC express links should have lower latency (1 cycle) than mesh links (2-3 cycles).
This would make GEC express even more advantageous.

### 3. Add Injection Backpressure (P1)
Real NoCs have credit-based flow control. Our traces inject without waiting for credits.
This underestimates congestion under high load.

### 4. Add VC Count Knob (P2)
Test with 2, 4, 8 VCs to find optimal buffer allocation.

### 5. Clean Up Synthetic Traces (P2)
Delete llama_C*_R*.trace (synthetic) and cli_test.trace/input.trace (duplicates).
Keep only real traces: llama_1b_*.trace, qwen3_*.trace, hpc_*.trace.
