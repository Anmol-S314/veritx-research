# VeritX modelling language

Terms for explicit workload memory demand. Demand and storage are separate
quantities; neither implies a duration or cache result.

## Language

**Tensor**:
An identity-bearing collection of elements with a declared byte extent that
persists across accesses.
_Avoid_: Operand allocation, inferred working set

**Tensor shard**:
A disjoint logical portion of a tensor placed at an explicitly owned physical
address range.
_Avoid_: Replica, workload rank

**Owner endpoint**:
The attached target that owns a shard's physical address range. It is distinct
from the issuer accessing that range.
_Avoid_: HBM device number, implicit local owner

**Access demand**:
Explicit READ or WRITE payload requested by a workload, including repeated
accesses to persistent storage.
_Avoid_: Collective bytes, storage capacity

**Transaction padding**:
Bytes counted around an exact payload slice to account for a memory transaction
granularity; they are not additional requested or authorized payload.
_Avoid_: Useful bytes, implicit adjacent access

**Access completion**:
The point at which all requests generated by an access have returned, releasing
its explicit completion dependencies.
_Avoid_: First child completion, request injection, memory durability

**Child visibility**:
The point at which one request's byte write takes effect or its read snapshot is captured. It does not make a multi-request access atomic.
_Avoid_: Parent atomic commit, DRAM durability

**Retry snapshot**:
The retained response of an original accepted request, returned for a matching retransmission rather than reading or writing memory again.
_Avoid_: Cache hit, new read, automatic loss recovery

**Endpoint epoch**:
The lifetime of endpoint retry identities between drained resets. Persistent tensor bytes may outlive an epoch.
_Avoid_: Tensor lifetime, compute reset
